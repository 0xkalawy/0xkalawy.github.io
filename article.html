Following a harmless-looking navigation race into an inconsistent security state.

Browsers are very good at maintaining boundaries. The interesting bugs often appear when two subsystems disagree about which boundary they are maintaining.

The setup

This page is a visual prototype for long-form research. The technical story is placeholder copy, but the reading experience is real: focused measure, clear hierarchy, useful side navigation, and code that stays readable.

The assumption

Imagine a document that begins a cross-origin navigation while a second subsystem still holds a reference to the old execution context. Each component behaves correctly in isolation. Their shared timeline is where the assumption becomes visible.

const oldOrigin = frame.contentWindow.origin;
frame.location = target;

await navigationStarted(frame);
assert(oldOrigin !== frame.contentWindow.origin);

Tracing the state

The useful move was to stop treating navigation as one event. Logging each transition separately revealed a short interval where ownership had changed but one cached decision had not.

Security boundaries rarely disappear. More often, two pieces of code briefly draw them in different places.

The diagram from the homepage would live here at full size, followed by reproduction notes, affected versions, and the disclosure timeline.

Takeaways

  • Model transitions, not only steady states.
  • Record which object made each security decision.
  • Treat cached authority as carefully as cached data.
